Web frontend

How mnemo-web is organised, and the shared pieces every screen uses.

The shape of mnemo-web

The UI is React and TypeScript, built with Vite. The notes editor is built on ProseMirror. Code is grouped by feature, in folders like src/notes, src/flashcards and src/settings, and talks to the host through a small typed fetch wrapper.

House rules

  • Style with the design tokens in src/styles/tokens.css. No hex colours or rgba() in component code.
  • Icons come from the AppIcon wrapper, not straight from lucide.
  • Popovers, dropdowns and menus use Radix. Never hand roll positioning.
  • Server state goes through React Query.
  • Every string a person can read is a translation key, through the useT() hook, in all five languages.

oxlint is the floor, and the hook rules are errors, not warnings.

Shared pieces

toastReports what happened. Long work keeps one progress toast and updates it, instead of raising a second one.
dialog.confirm and dialog.promptAsk one question and wait for the answer. Questions queue rather than stack.
ModalFor anything with fields or more to look at. Handles focus, Escape and the backdrop for you.
PopoverA thin wrapper over Radix in src/components/ui/popover.tsx.
TooltipsOne shared tooltip that moves to whatever you hover.

Stacking order lives in one place, src/lib/z-layers.ts. Use those tiers rather than inventing a z index.

Overlays

A file ending in Overlay is a convention, not a component. It decides whether a feature's surface is on screen at all, and gets mounted once in src/App.tsx beside the others.

Something unclear or missing? Tell us on GitHub.
